# CLAUDE.md — forsgren

Guidance for Claude Code in this repository.

## What this repo is

forsgren measures the five DORA metrics for a set of GitHub repositories from
GitHub data, and publishes them as a small static page (see
[README.md](README.md)).
A new contributor starts at [docs/getting-started.md](docs/getting-started.md)
(forsgren#436), which README.md and CONTRIBUTING.md link.
It is written in Go: one module, `github.com/yveshanoulle/forsgren`.

## Build and quality gates

- **`./FBP.sh "<message>"`** (FBP = FullBuildAndPush) — the local run: `gofmt -w` → `./sfl.sh pre` → `./Scripts/build_site.sh` → `./sfl.sh post` → commit, and push only when everything is green. A run that ends with exit 0 without reaching its last statement (an unbound variable under bash 3.2) is reported as `Aborted ❌` and exits 1 (forsgren#136). `sfl.sh` stops a phase at its first red gate (forsgren#441): the later gates are printed `⏭ skipped` and named, FBP skips the build and POST phase, and the ordinary red still commits locally with the subject `*** RED ****` (no push); a secret-class red commits nothing. `./FBP.sh --all` and `./sfl.sh --all` run every gate. `./FBP.sh --no-commit` runs the gates and the build only. A push refused because the remote moved is rebased over incoming commits that touch none of the local commits' files and pushed with a `⚠️` git row (CI tests that combination, not the run), at most 3 pushes; an overlap or a conflict stops red, the local commits untouched (`Scripts/fbp_push_or_rebase.sh`; forsgren#283).
- **Exit-trap completion** (forsgren#136, #137): a script under `set -e` with a top-level EXIT trap sets `COMPLETED=1` as its last statement and the trap turns an exit of 0 without it into exit 1, because bash 3.2 ends such a script with status 0 on an unbound variable; `Scripts/check_exit_trap_completion.sh` (self-test `test_check_exit_trap_completion.sh`) reads the source, `Scripts/test_exit_trap_completion_behaviour.sh` injects an abort into the real scripts. A new `set -e` script with a trap needs the idiom.
- **No producer piped into `grep -q`** (forsgren#428, found by #425): under `set -o pipefail` grep leaving at its first match can kill the producer with SIGPIPE and a present pattern reads as missing once the output passes the pipe buffer. Scripts end such a pipe in `has` (`Scripts/lib_has.sh`, sourced, reads all of stdin first); `Scripts/check_pipe_grep_q.sh` (self-test `test_check_pipe_grep_q.sh`) is red on `| grep -q` and any flag cluster with q. A script that runs in a sparse or copied checkout (the DCO push check, the fixture site build, the shellcheck gate) uses a here-string instead of the helper.
- **Node and npm** (forsgren#2, decision #190): `.nvmrc` holds the Node major (one line, currently `26`); `sfl.sh` runs `Scripts/check_node_pin.sh` after the tool install (red with the `brew` fix when the running major differs) and `Scripts/npm_sync_install.sh` (`npm ci` when `node_modules` or its stamp `node_modules/.package-lock.sha256`, lockfile sha256 + `node<major>`, is missing or stale); the **npm lockfile sync** gate (`Scripts/check_npm_lock_sync.sh`) is red when `package.json` and `package-lock.json` disagree; CI sets Node up from `.nvmrc` with a sha-pinned `actions/setup-node`, kept by `Scripts/test_workflow_node_pin.sh`.
- **Before handing back** (forsgren#439): Writers run their tests red first, and FBP (fail fast, forsgren#441) is the check.

Private names: this repository is public, so no tracked or untracked (not ignored) file or path may name a private repository. `Scripts/check_private_names.sh` (secret-class, PRE) searches `git ls-files` and `git ls-files -o --exclude-standard` for the names in `~/.config/forsgren/private-names` (or `FORSGREN_PRIVATE_NAMES_FILE`), locally, and in CI for the newline-separated Actions secret `FORSGREN_PRIVATE_NAMES`, which `quality.yml` passes to the PRE step; no list at all, an env list with no names, or a missing names file is exit 2, while a local names file that exists but holds no names passes with `0 names searched`. The local file is the source of truth; the Actions secret and the Dependabot secret of the same name are synchronized copies, never edited on their own: after changing the file, run `./Scripts/sync_private_names_secrets.sh` by hand (needs the maintainer's `gh` login), which sets both for the repository the clone's `origin` remote names (or `SYNC_REPO=<owner>/<repo>`; no tracked file writes it). An external fork pull request receives neither secret, so the gate fails there (exit 2, no list, the line naming the Actions secret `FORSGREN_PRIVATE_NAMES` whenever `GITHUB_ACTIONS` is `true`); that is intended: CI always fails without the secret or with an emptied one. An empty `FORSGREN_PRIVATE_NAMES_FILE` counts as unset (`private_names_file_given`, `Scripts/lib_private_names.sh`). `FBP.sh` also refuses a commit message that names a private name, first of all (`Scripts/check_private_names.sh --message -`, same list and matching, the message on stdin, never in a file; with no list or an empty one it passes): no commit, no gate run, one `❌` line that never holds the name or the message, exit 1. Locally, `FBP.sh` creates an empty list file when none exists (`Scripts/ensure_private_names_file.sh`), so the gate passes with `0 names searched`; CI never does. The gate leaves out the repository's own name (canon v2, forsgren#241): the basename of the `origin` remote (https, scp or ssh, with or without `.git`, ignoring case) is not private inside that repository, in the tree scan and in `--message`; every other listed name stays blocked, a repository with no origin keeps every name, and the output never prints a name. Never write a real private name in a file, test, comment or commit: use made-up names such as `acme-secret-repo`, and say "another estate repository" for a source repository.

## Code Health (CodeScene MCP), for every Go change

Adopted from another estate repository by Yves on 2026-10-02. An in-session check, deliberately not an sfl or CI gate.

- **Before the FBP of a Go change**, review the changed files with the CodeScene MCP (`code_health_review`, or `analyze_change_set` for several). Report each changed file's score in the hand-off.
- **Floor 9.0:** every Go file stays at 9.0 or above. Warn the moment a change would drop a file below it, and fix it before the FBP.
- **Scoreboard and ratchet:** [codescene-scores.json](codescene-scores.json) holds a row per Go file. `minScore` is the score minus 0.1 for a file below 10 (never below 9.0), and exactly 10.0 for a file at 10.0. Never drop a file below its `minScore`; lift it when a score improves. Update the rows of every reviewed file at each hand-off, and add a row for every new Go file.
- **Rules:** [.codescene/code-health-rules.json](.codescene/code-health-rules.json) puts the cyclomatic-complexity warning at 7 for all Go code, tests included, mirroring `.golangci.yml`'s gocyclo (min-complexity 6, tests included). Change both together.
- **On a Mac without the CodeScene MCP**, say so in the hand-off instead of a score. Never report a score from memory.
