# Scripts/ci_job_groups.txt
#
# Which CI job runs which gate (forsgren#259, decision #260). One row per
# gate that does NOT run in the main job:
#
#   <job>|<label of the row in Scripts/gate_report_order.txt>
#
# Every gate this file does not list runs in the main job, so a new gate is in
# one job and never in none. Scripts/run_ci_phase.sh reads it (its optional
# fourth argument is the job) and is red when a label here is no row of the
# order file. The label must be the exact label of the order file; the phase
# comes from the order file. Scripts/test_quality_jobs.sh pins the rows below
# and the jobs of both workflows.
#
# TWO WORKFLOWS (forsgren#686). Each job below belongs to one of two workflows:
# the one whose step runs `./Scripts/run_ci_phase.sh <phase> "$ROWS" "$DETAILS" <job>`.
#   .github/workflows/quality.yml    Quality: the real gates, in the jobs
#                                    quality (the main job: every row listed
#                                    nowhere here), quality_2, lint, workflows
#                                    and browser_3
#   .github/workflows/selftests.yml  Self-tests: the tests of the gates
#                                    themselves, in the jobs selftest_mac_1,
#                                    selftest_mac_2, selftest_linux,
#                                    isolation_1, isolation_2, summary,
#                                    browser_1 and browser_2
# THE RULE: a self-test row is a row whose label ends in " self-test" or starts
# with "mutation: ", and the step summary isolation gate, which runs the
# self-tests that write to the step summary and so is a self-test in full (the
# git sandbox isolation self-test already ends in " self-test"). Self-test rows
# run in selftests.yml, every other runnable row in quality.yml. The one
# exception: the secret-scan self-test is secret-class (its first case scans
# the real tree, forsgren#570), so it stays in Quality's main job and in every
# local run, before a commit. Scripts/test_gate_wiring.sh (pin 8) proves that
# every runnable row runs in exactly one of the two workflows, the one the rule
# names; Scripts/selftest_rows.sh lists the rows of selftests.yml's jobs, which
# sfl.sh skips locally by default (--with-selftests runs them).
#
# The isolation jobs: the slowest gate that no other gate waits for (measured in
# forsgren#259, step 1). Since forsgren#425 the step summary isolation gate has
# its own job, below: together the two took 15 minutes (the git sandbox
# self-test 9 min 27 s, the step summary gate 4 min 15 s, the setup 1.5 min).
#
# SHARDS (forsgren#426). The git sandbox isolation self-test runs its git-using
# self-tests in two shards, one job each. A row may carry a third field, the
# arguments the job runs the gate with:
#
#   <job>|<label>|<args>
#
# so the same label may stand in several jobs, each with its own shard. The
# self-test takes --shard N/M and runs every M-th self-test of its sorted list
# (index modulo M), so every self-test runs in exactly one shard and a new one
# lands in one by itself; the runner records each row as `<label> (shard N/M)`,
# and Scripts/merge_quality_report.sh joins the shards into the gate's one row,
# red when a shard is red or reported nothing. Another long gate shards the
# same way: add its rows here with --shard, one job each, and the jobs in
# the workflow (Scripts/test_quality_jobs.sh pins the jobs it knows).
isolation_1|git sandbox isolation self-test|--shard 1/2
isolation_2|git sandbox isolation self-test|--shard 2/2
#
# The summary job (forsgren#425): the step summary isolation gate alone, so it
# runs beside the git sandbox self-test and not after it.
summary|step summary isolation

# The browser self-test jobs (forsgren#447, #641). Measured on five green

# browser_1 and browser_2: the browser gate self-test in two shards, dealt by

# fixture site self-test (forsgren#686: it ran in browser_3 beside the browser
# gates; Scripts/build_fixture_site.sh runs go build, so browser_1 lists go and
