# Tools this repo's gates need, one per line. Read by Scripts/install_tools.sh.
#
# WHY A FILE. The installer script is meant to be IDENTICAL in every repo of
# the estate, so the thing that differs between repos, the list, cannot live
# inside it (same reason as Scripts/gate_report_order.txt).
#
# ONLY WHAT THE GATES USE TODAY. The installer has no notion of a tool "not
# used yet": every listed tool is installed or upgraded on every sfl run, and
# a name it cannot make runnable fails the run. So each later step of the
# forsgren#1 ladder adds its own tool here in the same change as its gate:
# node for the npm linters (step 5; the linters themselves are pinned in
# package.json and installed by `npm ci`, not by brew), shellcheck and
# yamllint (step 10), actionlint (step 15).
#
# NOT the Go tools. golangci-lint, deadcode and govulncheck are pinned through
# `tool` directives in go.mod plus go.sum (Yves's ruling on forsgren#1, step
# 17), so one version serves CI and here. Do NOT add them to this list:
# Homebrew has no lockfile, and the pinned copy would then be shadowed by
# whatever the formula publishes today.
#
# GO IS LISTED, BUT NOT TRUSTED FOR ITS VERSION. The installer has no version
# floor, and `brew install go` also upgrades an outdated Go machine-wide. What
# pins forsgren's Go is go.mod's `toolchain` line, exported as GOTOOLCHAIN by
# sfl.sh and FBP.sh (Scripts/go_toolchain.sh); Go downloads that toolchain on
# first use. See "Installing and updating" in README.md.

# Secret scanning. sfl exits 2 on a finding, so this one being absent would
# turn the strictest gate in the repo into a skipped step.
gitleaks

# Scripts/check_go_tests.sh, check_gofmt.sh and build_site.sh.
