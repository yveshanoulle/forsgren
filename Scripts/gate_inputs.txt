# Scripts/gate_inputs.txt (forsgren#262, step 1 of 3)
#
# What each of the four browser gates, the release workflow gate (forsgren#263) and the step summary isolation gate (forsgren#264) read, so a gate runs only when a commit touches one of its inputs.
# Scripts/lib_gate_select.sh (step 2) reads it: gate_select <label> says run or
# skip, and sfl.sh asks it before each of the four rows (step 3): a skipped row is
# not run, named with the reason and logged in .build/sfl-skips.log. CI runs all.
#
# One line per input:
# <label>|<kind>|<path>
#
# label: the gate's label exactly as Scripts/gate_report_order.txt writes it.
# kind:  in  = a file, or a directory (ends in /) with everything under it, that
#              the gate reads or builds from;
#        out = a pattern the gate never reads, excluded from the `in` trees above it
#              (forsgren#281): *_test.go is never compiled into the binary that
#              go build makes, and a testdata/ file (the goldens included) reaches
#              the site only through a go:embed line or a build script, which
#              Scripts/test_gate_inputs.sh holds to be none.
# path:  relative to the repository root.
#
# The script inputs are the closure of the gate's script: every Scripts/ file it
# names, followed transitively. Scripts/test_gate_inputs.sh derives the closure and
# is red when a script or data file of it is not listed here. The non-script
# inputs are written out: cmd/ and internal/ (the Go the site is built from),
# go.mod and go.sum, package.json and package-lock.json (node_modules, from
# npm ci), the fixture data and the required-pages manifest.
#
# UNRELATED FILES. The label `none` holds `out` rows for the files no browser gate
# reads: workflows, docs, markdown, the release scripts, and the two runners
# sfl.sh and FBP.sh (forsgren#284): they run the browser rows, but no browser gate
# reads them, so their effect is covered by the gate wiring, sfl and FBP
# self-tests, not by the browser rows. A changed file one of
# those rows names is known and selects nothing, instead of falling to the
# fail-safe. A file under Scripts/ that is in the closure of no gate's script is
# unrelated too (gate_unrelated_script in Scripts/lib_gate_select.sh), so another
# gate's script selects nothing. Everything else that no row names (a new
# top-level directory, a root file not listed) still selects every gate.
none|out|.github/**
none|out|docs/**
none|out|*.md
none|out|Scripts/release_*.sh
none|out|Scripts/test_release_*.sh
none|out|sfl.sh
none|out|FBP.sh

# NOT LISTED, ON PURPOSE: install/README.md is embedded (install/install.go) but is
# not part of the rendered site, so no browser gate reads its content. It is left
# to the fail-safe of step 2: a file no list names selects every gate.
# Scripts/testdata/fixture_site/ is under testdata/ but is listed: it is the
# data the fixture gate builds its site from, by design, and the guard allows
# that one path.
#
# The closure follows every name, comments included, so it is wide: browser_gate.mjs
# names its own self-test, which sources lib_selftest.sh. A wider list only selects a
# gate more often, never less.
#
# Each of the self-tests starts Chrome on pages it writes itself, so it reads no
# Go tree; the fixture self-test's case 7 builds the fixture site, so it does.

# --- step summary isolation (forsgren#264) --------------------------------
# Scripts/test_step_summary_isolation.sh finds the scripts of Scripts/ that write
# the step summary and runs every self-test that names one of them
# (Scripts/lib_summary_writers.sh). So what it reads is not the closure of its own
# script but the closure of those writers and of those self-tests, which
# Scripts/test_gate_inputs.sh derives with the gate's own discovery and holds
# listed. It is wide on purpose: the closure follows every name. The one exception is
# Scripts/test_gate_wiring.sh, which names most gate scripts, greps them and runs none (SUMMARY_TEXT_ONLY): it counts with what it sources.
# THE BLIND SPOT is a script added later. The `grep` row below is the gate's own
# discovery rule as a selector rule: a changed script of Scripts/ whose text says
# GITHUB_STEP_SUMMARY selects the gate even before the list names it. A new
# self-test that names a writer is not caught by that rule; Scripts/test_gate_inputs.sh
# is red for it, so the commit that adds it cannot land without listing it.
