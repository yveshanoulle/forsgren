# Scripts/gate_report_order.txt
# Canonical gate order, phase and labels for the run report.
#
# One line per gate:
# <label>|<script>|<phase>|<class>
#
# phase:
#   pre  = validates repository inputs and checker behaviour before the site
#          is generated
#   post = validates the generated site in .build/site
#
# class:
#   secret-class = a failure blocks commit as well as push
#   empty        = ordinary quality failure
#
# Ported from konenki-website 2026-10-01 (forsgren#1, ladder steps 1 to 3;
# the npm rows in step 7; HTMLHint, Stylelint and lint coverage in step 8;
# the required-pages rows in step 9; the privacy rows in step 10; the HTML
# duplication rows in step 11; shellcheck, yamllint and stray tracked files
# in step 12).
# sfl.sh dispatches every gate FROM this file, in file order, filtered by the
# phase field, so the labels it prints are the labels declared here.
# Scripts/test_sfl_drives_from_order_file.sh pins that sfl names no label
# literally, that every row names an executable script, and that every
# Scripts/test_*.sh is declared by a row.
#
# CANON LABELS, CANON ORDER. The labels and their order follow the estate
# canon (web-infra's Scripts/check_site_gate_parity.sh, DEFAULT_CANON), so
# forsgren's report reads like the other sites'. Only the rows whose scripts
# exist are here, plus the two privacy-pages rows, declared `n/a` with their
# reason as coachretreat-website and agilelean-website declare them: each
# later step of the forsgren#1 ladder adds its own rows at their canon
# position. Rows that are not canon (build site, Go tests, gofmt, the FBP
# fixtures, repository links) sit where konenki-website puts its own extras:
# the build-site self-test after the pull contract, the FBP fixtures after the
# step table.
#
# Checker SELF-TESTS run before the gate they validate, and belong in pre
# even when the checker they exercise belongs in post: a green from a
# checker nobody validated is worth nothing.
#
# FBP.sh:
#   gofmt -w -> pre gates -> Scripts/build_site.sh into .build/site
#   -> post gates -> commit/push
#
# THE SECRET PAIR LEADS, SELF-TEST FIRST. Nothing runs before the secret check,
# and the self-test runs before the gate it validates: a green from a checker
# nobody validated is worth nothing. If a refactor broke the regex in
# check_secrets.sh it would report "no leaks found" on a tree that has one.
# The secret scan is the only secret-class row: its exit 2 makes sfl exit 2
# and FBP.sh refuse to commit.
secret-scan self-test|Scripts/test_check_secrets.sh|pre|
secret scan|Scripts/check_secrets.sh|pre|secret-class
#
# THE DATA GUARD (forsgren#1, ladder step 6). Not canon: forsgren's own rule
# that the repository holds code only, and an installation's config and data
# live outside it, passed as paths. Red on installation config or data
# tracked outside testdata/, and on a name from FORSGREN_PRIVATE_NAMES_FILE
# (a file outside the repo) in a fixture or test file. It sits beside the
# secret pair because it guards the same thing, what must never reach a
# public history, and it is an ordinary-class row: a finding still commits
# locally and blocks the push. Self-test first, as for the secret pair.
data guard self-test|Scripts/test_check_data_guard.sh|pre|
data guard|Scripts/check_data_guard.sh|pre|
#
# Remote synchronisation is pre-flight infrastructure in sfl, not itself a
# gate; its fixture pins the ff-only/no-auto-rebase contract.
sfl pull contract|Scripts/test_sfl_pull.sh|pre|
#
# Repository dependency/tooling policy (forsgren#1, ladder step 7). These
# govern what subsequent gates execute, so they belong before the build.
# The gate is konenki-website's, byte-identical: exact devDependency pins in
# package.json, package.json and package-lock.json committed (or on their way
# into this run's commit) and not gitignored, node_modules never tracked.
# Its self-test is forsgren's own (no repo of the estate has one) and, being
# non-canon, sits right before the canon row it validates.
npm manifest policy self-test|Scripts/test_check_guardrail_packages.sh|pre|
npm manifest policy|Scripts/check_guardrail_packages.sh|pre|
#
# Tool installer contract (Scripts/install_tools.sh, identical across the
# estate). The tools it provides govern every gate after it, so its fixture
# runs before the build.
tool install self-test|Scripts/test_install_tools.sh|pre|
#
# The Go pin: sfl.sh and FBP.sh export GOTOOLCHAIN from go.mod's toolchain
# line via Scripts/go_toolchain.sh.
Go toolchain pin self-test|Scripts/test_go_toolchain.sh|pre|
#
# The Go generator (cmd/forsgren render) and the site build around it.
build-site self-test|Scripts/test_build_site.sh|pre|
#
# HTMLHint and Stylelint validate the generated site (forsgren#1, ladder step
# 8), at konenki-website's position, right after the build-site self-test.
# Both lint .build/site by default and accept a site-directory argument, so a
# caller can lint another build. Configs .htmlhintrc and .stylelintrc.json are
# konenki-website's, byte-identical. Each self-test is forsgren's own (no repo
# of the estate has one), drives the REAL linter, and, being non-canon, sits
# right before the canon row it validates: it runs in pre, the gate in post.
HTMLHint self-test|Scripts/test_gate_htmlhint.sh|pre|
HTMLHint|Scripts/gate_htmlhint.sh|post|
Stylelint self-test|Scripts/test_gate_stylelint.sh|pre|

#
# The required-pages manifest (forsgren#1, ladder step 9), at its canon
# position after Stylelint (forsgren has no deployed-pages self-test, the
# canon row between them). The manifest is internal/page/required-pages.json,
# hand-authored beside the templates and never generated: build_site.sh
# renders HTML, it does not write or copy the manifest. Validator and
# self-test are konenki-website's, adapted only in the manifest path; the
# self-test adds forsgren's own cases at its end, pinning the named reason of
# a missing manifest and of an empty list, each with a mutation proof. The
# self-test drives synthetic manifests, so it runs in pre; the validator
# runs in post, as in konenki.
required-pages self-test|Scripts/test_validate_required_pages.sh|pre|
required-pages manifest|Scripts/validate_required_pages.sh|post|
#
# HTML duplication, a RATCHET (forsgren#1, ladder step 11), at its canon
# position after the required-pages rows (forsgren has none of the release
# and workflow-pin rows between them). konenki-website runs both rows in
# pre, over its authored SiteSource/ only: its generated pages repeat the
# composed chrome by design. Yves's ruling for forsgren: ported even with one
# page, measured on the templates AND on the generated page. So the canon
# pair is konenki's choice, pre, over the authored source
# (internal/page/templates, ceiling 0.00%); the generated-page row is
# forsgren's own, a wrapper calling the same script on .build/site with its
# own ceiling (0.00%), and runs in post, since that page exists only after
# the build, right behind the canon row it extends. One self-test, in pre,
# covers both: it builds its own copy of the site into a temp dir. jscpd
# 4.2.4 is a pinned devDependency run by path (konenki fetches the same
# version with npx). Both rows are red on zero .html files scanned, with
# that reason.
html-duplication self-test|Scripts/test_check_html_dupl.sh|pre|
html duplication|Scripts/check_html_dupl.sh|pre|
html duplication, generated page|Scripts/check_html_dupl_site.sh|post|

#
# Shellcheck and yamllint (forsgren#1, ladder step 12), at their canon
# position after the html-duplication rows and before lint coverage (forsgren
# has no gate-wiring or actionlint rows yet, the canon rows between them; the
# non-canon Go rows above sit where konenki puts its own extras). Both read
# repository source, so both run in pre.
# The shellcheck gate and its self-test are web-infra's, the estate canon:
# targets DERIVED from `git ls-files`, every *.sh plus every extension-less
# file with a bash or sh shebang, so a new script is covered the moment it is
# tracked. The self-test is byte-identical; the gate is adapted only in
# comments that named web-infra's own files. konenki-website runs an older,
# named-list copy without the self-test.
# The yamllint gate is konenki-website's, adapted in its targets: konenki
# names .github/workflows/, which forsgren does not have yet, so the targets
# are derived the shellcheck way, every tracked .yml/.yaml (.yamllint.yml
# included, so the list is never empty, and zero is red). Its self-test is
# forsgren's own (no repo of the estate has one) and, being non-canon, sits
# right before the canon row it validates. .yamllint.yml is konenki's, the
# rules unchanged, adapted only in its header comment.
shellcheck self-test|Scripts/test_check_shellcheck.sh|pre|
shellcheck|Scripts/check_shellcheck.sh|pre|
yamllint self-test|Scripts/test_check_yamllint.sh|pre|
yamllint|Scripts/check_yamllint.sh|pre|
