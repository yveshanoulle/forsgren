# Scripts/gate_report_order.txt
# Canonical gate order, phase and labels for the run report.
#
# One line per gate:
# <label>|<script>|<phase>|<class>
#
# phase:
#   pre  = validates repository inputs and checker behaviour before the site
#          is generated
#   post = validates the generated site in .build/site
#
# class:
#   secret-class = a failure blocks commit as well as push
#   empty        = ordinary quality failure
#
# Ported from konenki-website 2026-10-01 (forsgren#1, ladder steps 1 to 3;
# the npm rows in step 7).
# sfl.sh dispatches every gate FROM this file, in file order, filtered by the
# phase field, so the labels it prints are the labels declared here.
# Scripts/test_sfl_drives_from_order_file.sh pins that sfl names no label
# literally, that every row names an executable script, and that every
# Scripts/test_*.sh is declared by a row.
#
# CANON LABELS, CANON ORDER. The labels and their order follow the estate
# canon (web-infra's Scripts/check_site_gate_parity.sh, DEFAULT_CANON), so
# forsgren's report reads like the other sites'. Only the rows whose scripts
# exist are here: each later step of the forsgren#1 ladder adds its own rows
# at their canon position (HTMLHint, Stylelint, required pages and privacy
# are post rows). Rows that are not canon (build site, Go tests, gofmt, the FBP fixtures) sit where
# konenki-website puts its own extras: the build-site self-test after the
# pull contract, the FBP fixtures after the step table.
#
# Checker SELF-TESTS run before the gate they validate, and belong in pre
# even when the checker they exercise belongs in post: a green from a
# checker nobody validated is worth nothing.
#
# FBP.sh:
#   gofmt -w -> pre gates -> Scripts/build_site.sh into .build/site
#   -> post gates -> commit/push
#
# THE SECRET PAIR LEADS, SELF-TEST FIRST. Nothing runs before the secret check,
# and the self-test runs before the gate it validates: a green from a checker
# nobody validated is worth nothing. If a refactor broke the regex in
# check_secrets.sh it would report "no leaks found" on a tree that has one.
# The secret scan is the only secret-class row: its exit 2 makes sfl exit 2
# and FBP.sh refuse to commit.
secret-scan self-test|Scripts/test_check_secrets.sh|pre|
secret scan|Scripts/check_secrets.sh|pre|secret-class
#
# THE DATA GUARD (forsgren#1, ladder step 6). Not canon: forsgren's own rule
# that the repository holds code only, and an installation's config and data
# live outside it, passed as paths. Red on installation config or data
# tracked outside testdata/, and on a name from FORSGREN_PRIVATE_NAMES_FILE
# (a file outside the repo) in a fixture or test file. It sits beside the
# secret pair because it guards the same thing, what must never reach a
# public history, and it is an ordinary-class row: a finding still commits
# locally and blocks the push. Self-test first, as for the secret pair.
data guard self-test|Scripts/test_check_data_guard.sh|pre|
data guard|Scripts/check_data_guard.sh|pre|
#
# Remote synchronisation is pre-flight infrastructure in sfl, not itself a
# gate; its fixture pins the ff-only/no-auto-rebase contract.
sfl pull contract|Scripts/test_sfl_pull.sh|pre|
#
# Repository dependency/tooling policy (forsgren#1, ladder step 7). These
# govern what subsequent gates execute, so they belong before the build.
# The gate is konenki-website's, byte-identical: exact devDependency pins in
# package.json, package.json and package-lock.json committed (or on their way
# into this run's commit) and not gitignored, node_modules never tracked.
# Its self-test is forsgren's own (no repo of the estate has one) and, being
# non-canon, sits right before the canon row it validates.
npm manifest policy self-test|Scripts/test_check_guardrail_packages.sh|pre|
npm manifest policy|Scripts/check_guardrail_packages.sh|pre|
#
# Tool installer contract (Scripts/install_tools.sh, identical across the
# estate). The tools it provides govern every gate after it, so its fixture
# runs before the build.
tool install self-test|Scripts/test_install_tools.sh|pre|
#
# The Go pin: sfl.sh and FBP.sh export GOTOOLCHAIN from go.mod's toolchain
# line via Scripts/go_toolchain.sh.
Go toolchain pin self-test|Scripts/test_go_toolchain.sh|pre|
#
# The Go generator (cmd/forsgren render) and the site build around it.
build-site self-test|Scripts/test_build_site.sh|pre|
#
# go test ./... over the module. Red on a failing test AND on zero tests
# found: a green over nothing measured is the false clean this gate exists
# to prevent.
Go tests self-test|Scripts/test_check_go_tests.sh|pre|
Go tests|Scripts/check_go_tests.sh|pre|
#
# CHECK-ONLY here (gofmt -l), as CI will call it. FBP.sh runs the same script
# with --fix before PRE, so locally the check sees an already-formatted tree.
gofmt self-test|Scripts/test_check_gofmt.sh|pre|
gofmt|Scripts/check_gofmt.sh|pre|
#
# Dependency audit belongs before generating deployable output (forsgren#1,
# ladder step 7). Both scripts are konenki-website's, byte-identical. sfl runs
# the self-healing npm_audit_check.sh (one `npm audit fix`, re-verified; the
# lockfile change rides into the commit). konenki's CI-only step body and its
# fixture (report_npm_audit_step.sh) are not ported: forsgren has no CI
# workflow yet.
npm-audit self-test|Scripts/test_npm_audit_check.sh|pre|
npm audit|Scripts/npm_audit_check.sh|pre|
#
gate-failure summary|Scripts/test_summarize_gate_failure.sh|pre|
sfl drives from the order file|Scripts/test_sfl_drives_from_order_file.sh|pre|
step table|Scripts/test_render_step_table.sh|pre|
#
# FBP.sh's own summary and its build-site page count (konenki-website issues
# #6 and #8): repository-source presentation, like the report scripts above.
FullBuildAndPush commit-message block|Scripts/test_fbp_commit_message.sh|pre|
FullBuildAndPush build-site page count|Scripts/test_fbp_build_pagecount.sh|pre|
#
